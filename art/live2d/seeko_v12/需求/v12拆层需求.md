# 希可 Live2D v12：女仆装「动画拆层」需求

交付方：特蕾莎 · 提出：露娜 · 2026-10-28

## 为什么要重拆

v10 骨架做完一轮动作后，Yank 的结论是：动作太像机器人、拎起来很怪、只有头和四肢在动。
露娜回头看 PSD，根子在拆层上，不在绑定：

- **手臂没有关节余量**：`ArmUpper_L` 只是一团泡泡袖，没有肩头；`ArmLower_L` 是两端平切的一小截。只要转超过 10° 就露切口，所以所有动作都被迫做得很小 —— 挥手时手只抬到腰（见 `sheet_Wave0.png`）。
- **身子是一整块**：`DressBase` 把上衣和裙子画在一张图上，身子不能弯、裙子不能单独摆，拎起来时裙摆也垂不下来。
- **后发是左右两大片**，没法分缕飘；**腿是大腿小腿一体**，没有膝盖；**脖子太短**，不能拉伸。

所以这次请把女仆装按「能大幅度动」的方式重拆。**脸和眼睛嘴巴那一整套（见文末清单）不要动，逐像素保持 v05f。**

## 总规则（和以前一样）

1. 画布 1086×1448 不变，每个图层占满整个画布（Cubism 同名替换导入要对得上）。
2. **被别的图层盖住的部分也要画全**：肩头画成完整的圆球、小臂两端是圆头、裙子上沿往腰带里多画、大腿往裙子里多画。重叠区域不要留硬边、不要留半透明毛边。
3. 线稿粗细、上色风格和 v05f 一致，参考 `seeko_cubism_import_v05f.psd`。
4. 新图层名按下面的表起；旧图层名如果继续用，内容可以变，名字不变。
5. 交付：`seeko_cubism_import_v12.psd` + 平铺预览 `preview_v12.png` + 每个新/改图层单独一张的 `parts_v12_*.png` + `validation_v12.json`（像以前那样列出哪些层逐像素未变、哪些层改了）。

## 要改 / 新增的图层

### A. 手臂（左右各一套，`_L` / `_R`）— 最重要

| 图层 | 画什么 | 关键要求 |
| --- | --- | --- |
| `ArmUpper_L` | 泡泡袖 + 上臂，从肩到肘 | **顶端画成完整的圆球肩头**，直径约 85px，圆心在现在袖子顶端中心（左 ≈ (668,935)，右 ≈ (392,935)）；圆球藏在 `DressTop` 的袖笼后面。底端画到肘关节下方 25px，收成圆头 |
| `ArmLower_L` | 小臂，从肘到腕 | 顶端从肘关节上方 25px 开始、圆头；底端画到腕关节下方 20px、圆头。整体比现在长 ≈ 40px |
| `Cuff_L` | 袖口花边 | 画成完整一圈（现在只有正面半圈），因为抬手时会看到背面 |
| `Hand_L` | 现在的握拳手 | 手腕处画成圆头，往小臂里多画 20px |
| `HandOpen_L`（新） | 五指张开、掌心朝前的手 | 挥手、招手用；大小和 `Hand_L` 一致，腕口位置一致，默认隐藏 |

肘关节位置：左 ≈ (690,1035)，右 ≈ (425,1030)；腕：左 ≈ (760,1075)，右 ≈ (455,1075)。
上臂要能以肩球为轴转到 **水平举起 (90°)**，小臂能再弯 90°，转到位的时候不能露切口。

### B. 躯干

| 图层 | 画什么 | 关键要求 |
| --- | --- | --- |
| `DressTop`（新，替代 DressBase 的上半） | 蓝色连衣裙上身：领口到腰带 | 底边往下多画 40px 藏进腰带/裙子；**袖笼下面的侧身画全**（手臂抬起来时能看到腋下这块） |
| `SkirtBack`（新，替代 DressBase 的下半） | 裙子后片/底层：腰到下摆 | 顶边往上多画 40px 藏进腰带；这是裙子的「大块」，前面的 `SkirtFront` 褶片叠在它上面 |
| `SkirtInner`（新） | 裙子内侧 | 深色的裙内阴影面，形状 = 裙摆内侧一圈，默认几乎看不到；被拎起来、下落时裙子会往上翻，这时露出来 |
| `SkirtFront`、`SkirtHemLace` | 保留 | 顶边同样往上多画 30px |
| `BodiceWhite`、`Waistband`、`ApronBody`、`ApronLace`、`ChestLace_L/R`、`NeckCollar`、`NeckBow_L/R`、`Sapphire` | 保留 | `ApronBody` 顶边往腰带里多画 20px |
| `DressBase` | **删除**（被 DressTop + SkirtBack 取代） | |

### C. 脖子

| 图层 | 要求 |
| --- | --- |
| `Neck` | 画成完整圆柱：上端画进下巴里 40px，下端画进领口里 60px（现在总高 91px，改后约 190px）。被拎起来时脖子会被拉长一点，不能露底 |

### D. 腿（左右各一套）

| 图层 | 画什么 | 关键要求 |
| --- | --- | --- |
| `LegThigh_L`（新） | 大腿（白袜上段） | 顶端往裙子里多画 60px，底端到膝盖下方 20px、圆头 |
| `LegShin_L`（新） | 小腿（白袜下段 + 袜口） | 顶端从膝盖上方 20px 开始、圆头，到脚踝进鞋里 15px |
| `Shoe_L` | 保留 | 鞋口画全一圈 |
| `LegStocking_L` | **删除**（拆成上面两层） | |

膝盖位置：左 ≈ (620,1255)，右 ≈ (465,1255)。拎起来时腿要能前后晃 ±25°、小腿再弯 40°。

### E. 头发

| 图层 | 画什么 | 关键要求 |
| --- | --- | --- |
| `HairBack_Under`（新） | 最底层整块后发 | 一整片，形状 = 现在 HairBack_L + HairBack_R 的并集再往内缩 15px，颜色用后发的暗部色，不画细节。作用是所有发缕飘起来时后面不漏白 |
| `HairBack_L_Outer` / `HairBack_L_Mid` / `HairBack_L_Inner`（新，右边同样三层） | 把现在的 `HairBack_L` 拆成外 / 中 / 内三缕 | 缕与缕之间重叠 30px、各自画全（被盖住的边也画完整），每缕从发根（头顶侧面）一直到发尾 |
| `HairBack_L` / `HairBack_R` | **删除**（拆成上面三层） | |
| `HairSide_L/R`、`HairFront_L/C/R`、`Ahoge`、`FinEar_L/R`、`Headband`、`HairRibbon_L` | 保留 | `HairSide` 发根处往头里多画 20px |

### F. 不动的图层（逐像素保持 v05f）

`FaceBase`、`FaceHairShadow*`（6 层）、`Eye*` / `Eyelid*` / `IrisPupil*` / `EyeSocketMask*` / `EyeLine*` / `EyeHighlight*` / `EyeSparkle*`（左右全部）、`Tear_L/R`、`CheekBlush_L/R`、`SweatDrop`、`AngerMark`、`Eyebrow_L/R`、所有 `Mouth*`（22 层）。

## 图层顺序（从下到上）

HairBack_Under → HairBack_R_Inner/Mid/Outer → HairBack_L_Inner/Mid/Outer → LegThigh_R → LegShin_R → Shoe_R → LegThigh_L → LegShin_L → Shoe_L → SkirtInner → SkirtBack → SkirtHemLace → SkirtFront → ArmUpper_R → ArmLower_R → ArmUpper_L → ArmLower_L → DressTop → BodiceWhite → ChestLace_R/L → ApronLace → ApronBody → Waistband → NeckCollar → Hand_R → HandOpen_R → Hand_L → HandOpen_L → Cuff_R → Cuff_L → Neck → FaceBase → （脸部各层顺序不变）→ HairSide_R/L → HairFront_* → Ahoge → Eyebrow → Headband → HairRibbon_L → NeckBow_R/L → Sapphire

（手臂画在上衣后面、手在上衣前面，这样上臂抬起时肩球藏进袖笼，手垂着时在裙子前面 —— 和现在一样。）

## 验收时露娜会检查

1. 同名替换导入 v12 PSD 后，脸部各层 SHA256 和 v05f 一致。
2. 把每条手臂的肩旋转到 90°、肘再弯 90°：没有切口、没有露底。
3. 腿前后摆 25° + 小腿弯 40°：膝盖处不断。
4. 脖子拉长 15%：不露底。
5. 后发三缕各自摆 ±15°：缝隙处有 HairBack_Under 垫着，不漏背景。

参考图：`v12_split_marks.png`（在现在的立绘上标了拆分线和关节位置）、`sheet_Wave0.png` / `sheet_Hang0.png`（现在动作幅度有多小）。

有不清楚的地方直接问露娜，或者按你觉得更合理的方式拆、在交付说明里写清楚就行。
